# Web3 Career v0.2 — Immersive 3D Polish (Design Spec)

> Brainstormed: 2026-05-17
> Status: approved — ready for implementation plan
> Related: `frontend-PRD.md` §3 (design system), §10 (performance budget)

## Goal

Push the frontend visual quality from "clean dark crypto theme" to "intentionally immersive 3D Web3 site" by adding (a) a WebGL hero scene, (b) a fragment-shader background, (c) universal mouse-tracking 3D card tilt, and (d) a 3D bar chart on `/salaries`. The site must remain readable, accessible, and SEO-friendly.

## Non-Goals

- Do NOT add 3D to detail pages (`/jobs/[slug]`, `/learn/[slug]`, `/companies/[slug]`) — they prioritize legibility.
- Do NOT do scroll-driven camera parallax (defer to v0.3).
- Do NOT add custom mouse-cursor trails / particle cursors.
- Do NOT animate form submission states beyond what already exists.
- Do NOT change the color palette — the new 3D pieces must use the existing tokens (`cyan-glow #00f5ff`, `violet #a855f7 / glow #c084fc`, `lime #84cc16`).

## Background

v0.1 ships a working dark-themed Next.js 15 site with seven user-facing routes plus the static stubs. All page surfaces today rely on flat utility-class gradients (`aurora`, `grid-bg`), glassmorphism cards, and CSS animations. The current frontend has no 3D library and no shader work. The user wants stronger immersion ("crypto/web3 sites should feel three-dimensional") without losing the readability of the data-dense pages.

## Architecture

Four additive components living in `frontend/src/components/`. None of them replace existing layout; they overlay or wrap.

```
RootLayout
├── ShaderBg            ← fixed, z=-20, fragment-shader noise; replaces .aurora
├── GridBackground      ← unchanged (kept, sits on top of ShaderBg at z=-10)
├── SiteHeader, <main>, SiteFooter   ← unchanged
└── (per page)
    ├── HomePage
    │   └── HeroScene   ← dynamic({ ssr: false }), absolute-positioned right half
    ├── SalariesPage
    │   └── SalaryBars3D  ← dynamic({ ssr: false }), above existing tables
    └── any card (JobCard, CompanyCard, ArticleCard, dashboard Card, salaries KPI)
        └── <Tilt>...</Tilt>   ← client wrapper, mouse-driven perspective
```

3D components ship in a single chunk so the home page and salaries page share the bundle. Other routes (jobs detail, companies, dashboard, learn, auth, static stubs) do not load `three`.

## Components

### 1. `ShaderBg` (site-wide, replaces `aurora`)

**File:** `frontend/src/components/shader-bg.tsx` (`'use client'`)

**Behavior:**
- Mounts inside `RootLayout` body, fixed full-screen, `z-index: -20`, `pointer-events: none`.
- A single full-bleed `<canvas>` runs a fragment shader: layered 2D simplex noise modulated by time, colored by a 3-stop gradient (`#a855f7` → `#00f5ff` → `#84cc16`).
- Falls back to a static CSS gradient when:
  - SSR (canvas is hidden until hydrated; SSR'd fallback CSS visible)
  - WebGL context creation fails
  - `prefers-reduced-motion: reduce` is true (shader frozen at `time=0`)
- Bundle: bare WebGL, no Three.js — < 4KB minified.

**Why this replaces `.aurora`:** the existing CSS `.aurora` already does a 3-blob radial gradient; the shader gives the same vibe but with temporal motion at minimal cost.

**Decision:** `.grid-bg` overlay stays on top of the shader (it already animates, no reason to fold it in).

### 2. `Tilt` (universal card upgrade)

**File:** `frontend/src/components/tilt.tsx` (`'use client'`)

**API:**
```tsx
<Tilt max={8} className="...">{children}</Tilt>
```
- Always renders a `<div>` — callers pass the actual semantic element as a child (e.g. `<Tilt><Link href=...>...</Link></Tilt>`). No polymorphic `as` prop, keeps the wrapper trivially typed.

**Behavior:**
- Listens to `mousemove` on the element (with `pointer: fine` media query check so phones/tablets skip the listener).
- Computes a normalized `(-1..1)` x/y from the cursor's position over the element bounds.
- Applies `transform: perspective(1000px) rotateX(${-y * max}deg) rotateY(${x * max}deg)`.
- Adds a child `<div>` overlay with a moving radial gradient that fakes specular highlight.
- On mouse-leave, smoothly returns to neutral via CSS transition.
- `prefers-reduced-motion`: no-op (renders a plain `div` with the same classes).

**Where it's applied:**
- `JobCard` (entire site)
- `CompanyCard` in `/companies`
- `ArticleCard` in `/learn`
- Dashboard `Card` component
- `Kpi` cards on `/salaries`

**Where it is NOT applied:** Tag chips (too small), nav links, buttons, form inputs.

**Bundle:** zero dependencies, < 1KB gzipped.

### 3. `HeroScene` (home page only)

**File:** `frontend/src/components/hero-scene.tsx` (`'use client'`)

**Mount point:** `frontend/src/app/page.tsx` — wrapped with `dynamic(() => import('@/components/hero-scene'), { ssr: false, loading: () => null })`. Positioned `absolute right-0 top-0 w-1/2 h-full pointer-events-none hidden md:block`.

**Scene contents:**
- `<Canvas camera={{ position: [0, 0, 5.5], fov: 50 }} dpr={[1, 1.5]}>`
- A `<Float speed={1.2} rotationIntensity={0.4} floatIntensity={0.6}>` containing:
  - A wireframe `IcosahedronGeometry(1.4, 1)` with `meshBasicMaterial` color `#c084fc`, transparent opacity 0.85
  - 7 floating small wireframe cubes (`BoxGeometry(0.25)`) at randomized positions in `[-3..3]³`, cyan color `#67e8f9`, opacity 0.5
- Subtle `useFrame` loop: continuous slow Y-rotation on the parent group at `delta * 0.15`
- One distant `<pointLight color="#00f5ff">` at `[5, 3, 5]`, one `<pointLight color="#c084fc">` at `[-5, -3, 5]` — only matter if we add non-basic materials later, harmless now.

**No `<OrbitControls>`** — the scene drives itself; user input is rejected (canvas has `pointer-events: none`).

**Bundle:** `three` + `@react-three/fiber` + `@react-three/drei` (Float only) ≈ 120 KB gzipped, loaded only after home-page hydration.

### 4. `SalaryBars3D` (salaries page only)

**File:** `frontend/src/components/salary-bars-3d.tsx` (`'use client'`)

**API:**
```tsx
<SalaryBars3D rows={snap.byRole.slice(0, 10)} />
```

**Mount point:** `frontend/src/app/salaries/page.tsx` — wrapped with `dynamic(() => import('@/components/salary-bars-3d'), { ssr: false })`. Mounted between the KPI grid and the "By skill / role" table.

**Scene contents:**
- A `<Canvas camera={{ position: [0, 4, 10], fov: 45 }}>` at fixed height ~360px.
- A row of 10 bars along the X axis. For each row `r`:
  - `height = (r.avg_max / maxAvgMax) * 4` (max bar = 4 world units)
  - `<mesh position={[idx * 0.9 - 4.5, height/2, 0]}><boxGeometry args={[0.6, height, 0.6]}/><meshBasicMaterial color={lerpHex('#22d3ee', '#c084fc', r.avg_max / maxAvgMax)} transparent opacity={0.85} /></mesh>`
  - `lerpHex(a, b, t)` is a tiny local helper in the same file: parse two `#rrggbb`, lerp each channel, return `#rrggbb`. No external color library.
  - A drei `<Text>` above each bar showing `$Xk` (rounded thousands) and the role slug rotated -12° toward the viewer
- Group rotates slowly via `useFrame` (delta * 0.08 Y) for the cinematic effect.
- Floor plane: a faint wireframe grid (`<gridHelper args={[12, 12, '#1f2937', '#0f1729']}/>`).

**Bundle:** reuses the `three` chunk shared with HeroScene; salaries page costs nothing extra beyond a few KB for `<Text>`.

## Performance Budget

| Page | Existing FL JS | After v0.2 | Δ |
| --- | --- | --- | --- |
| Home (`/`) | ~180 KB | ~300 KB (hero + shader) | +120 KB |
| `/salaries` | ~180 KB | ~310 KB (shader + chart) | +130 KB |
| All other pages | ~180 KB | ~184 KB (shader only) | +4 KB |

LCP targets:
- Home LCP must stay ≤ 2.5s on 4G-slow throttle (SSR'd hero text is the LCP candidate; 3D canvas is decorative, mounts after hydration).
- `/salaries` LCP must stay ≤ 2.5s.

Reduce-motion fallback: if `prefers-reduced-motion: reduce`, both 3D canvases skip mounting entirely (the dynamic import is still requested but the component returns `null`).

## Accessibility

- All 3D canvases get `aria-hidden="true"` and are decorative; no information is presented exclusively in 3D.
- Salaries data is fully readable in the table beneath the 3D chart — the chart augments, never replaces.
- Tilt: pointer-coarse devices skip the tilt logic.
- Focus rings on cards are unaffected (Tilt wraps but does not interfere with `:focus-visible`).
- All keyboard navigation must continue to work; canvases have `tabindex="-1"`.

## Testing

- **Unit:** `Tilt` math: given a fake bounding rect + mousemove, computes the expected rotation. Vitest + `@testing-library/react`.
- **Visual smoke:** after each phase, restart frontend dev and curl the page; verify 200 + presence of new elements in DOM (e.g., a `canvas` in `/` and `/salaries`).
- **Bundle size assertion (informal):** run `pnpm next build --turbo=off` (or `next build`) and inspect the route summary — home + salaries First Load JS must stay under 320 KB.
- **Reduce-motion sanity:** with DevTools "Emulate prefers-reduced-motion: reduce", no canvas tags should appear in either page.

## Implementation Phasing

1. **P1 — Foundation (no new deps)**
   - Create `ShaderBg` and mount in `RootLayout`.
   - Create `Tilt` and apply to all 5 card types.
   - 2 commits, ~150 lines TSX, no `package.json` change.

2. **P2 — Hero (+ deps)**
   - `pnpm add three @react-three/fiber @react-three/drei` in `frontend/`.
   - Create `HeroScene`, mount on `/` with dynamic import.
   - 1 commit (deps + component), 1 commit (page wiring).

3. **P3 — Salaries 3D**
   - Create `SalaryBars3D`, mount on `/salaries`.
   - 1 commit.

4. **P4 — Verify & polish**
   - Restart frontend, curl all routes, check console for warnings, scan for hydration issues, manual smoke screenshot (if available).
   - 1 commit (empty marker).

## Resolved Decisions

- `.grid-bg` overlay stays on top of `ShaderBg` (separate layer).
- `Tilt` uses CSS transition for the return-to-neutral, not rAF smoothing.
- `ShaderBg` ships an inline GLSL simplex helper (no external lib).

## Risks

- **WebGL crashes on older browsers**: mitigated by feature detection in `ShaderBg` and `dynamic ssr: false` for r3f.
- **Tilt jitter in low-FPS Firefox**: mitigated by capping update frequency to one transform per animation frame.
- **Bundle creep** if `drei` is over-imported: enforce `import { Float, Text } from '@react-three/drei'` — never `import * from drei`.
- **iOS Safari smoothness**: r3f has known iOS quirks; the `dpr={[1, 1.5]}` cap keeps it sane.
