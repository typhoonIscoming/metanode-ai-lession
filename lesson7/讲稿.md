## [0:00 — 2:00] 开场

好，我们开始第七课。

上节课我们讲了 harness——把任务状态从 AI 的脑子搬到磁盘文件，让任务能跨会话续。但其实那一节有个**默认前提**没说破——一直是**一个 AI** 在跑活。Plan 文件再好，每次也只能一个 AI 读它、按它跑、回填它。

今天我们打破这个前提。今天的主题是 **agent 工作流**——多个 AI 同时干、互相讨论、自己分配工作。这件事在 2026 年正在从"实验性 demo"变成"主流工程实践"。

我给大家一个 Addy Osmani 在 2026 总结的判断，原话：**"你以前是和一个 AI 结对，现在你管一个 agent team。"** 这是个心态翻转——你从"用工具"变成"管团队"。

行业里有两条很有代表性的路，今天就讲这两条。第一条是 Anthropic 自己做的 **Claude Code Agent Teams**——它在 Claude Code 内部把多个 Claude 实例编排起来，让它们在**一次会话内**并行干活。第二条是 Nous Research 开源的 **Hermes Agent**——它做了一个完全独立的 agent 平台，不绑 Claude、不绑 Anthropic，长跑、多入口、模型无关，在 GitHub 上已经 155k stars。

这两个**不是竞品**——它们刚好对偶：一个是**内嵌型**（在 Claude Code 里的 feature），一个是**独立型**（自己跑在 VPS / serverless 上）。学完这节课，你能判断哪种场景该用哪个，甚至**两个一起用**。

讲义有四块：引子、Agent Teams、Hermes、对比 + 反模式。今天**以听讲为主**，演示我会现场跑给大家看，**你只需要看着配置文件、命令行长什么样、teammate 之间怎么对话**，不必跟着敲键盘。

环境确认——讲义 §〇 那 4 件事看一眼，没问题我们就开始。

## [2:00 — 4:00] §一 从单 agent 走到 agent team

第一块短一点，主要是建立心智模型。

你们前 6 课其实一直在和**一个** AI 打交道——你 prompt 一句、它干一句，写代码、跑回测、写 spec，都是单线推进。L6 我们给 AI 装了 plan 文件做外脑，让它能跨会话续命——但**还是单线**。

今天讲的 agent team，最大的变化是：**多个 AI 同时干活，每个都有自己的 context window，它们之间可以互相发消息、互相挑战、共享一份 task list**。

我口播一下讲义里那张对比表的关键差异：

第一行，单 agent 任务分发是你手工说"先做 A 再做 B"；agent team 是 lead 拆任务到 task list，其它 agent **自己 claim**——你不用管。

第二行，单 agent 沟通是你和 AI 单线；agent team 是 **agent 之间互发消息**——这是关键，不是你转发，是它们自己讲。

第三行，单 agent 适合大部分日常编码；agent team 的甜区在 **research / review / 多视角 debug / 跨层重构**——这些场景一个 AI 容易陷入单一视角，多个 AI 同时看不同侧面会更好。

我重点说最后一行——**瓶颈从生成转移到验证**。这是 Addy Osmani 的原话。意思是：以前 AI 写代码慢，瓶颈在 AI 那边；现在 5 个 AI 并行干活，AI 那边产能爆炸，**瓶颈变成了人——人怎么验、怎么收口、怎么综合判断**。

我们前几课讲的 spec、harness、verify 在 agent team 时代变得更重要——不是过时，而是**升级**：spec 还在那（agent team 仍然要按 spec 干），harness 还在那（agent team 仍然按 plan 文件协作），verify 还在那（lead 仍然要收 teammate 的输出）。差别是，所有这些都被并行化、放大了。

好，这是心智模型。下面看两个具体实现。

## [4:00 — 14:00] §二 Claude Code Agent Teams（内嵌型）

进入今天的重点之一。

**Agent Teams 是 Claude Code 的实验性 feature**——注意，**实验性**。要 Claude Code 版本 **v2.1.32 或以上**，并且**默认是关的**，要显式开启。

我先讲它和老的 subagent 的区别——这是讲清楚 Agent Teams 是什么的最快路径。

你们 L2 学过 subagent。Subagent 是什么？是 main agent 派一个跑腿——跑腿干完事、把结果汇报回来，main agent 收到结果继续干。**跑腿之间不能互相说话**。

Agent Team 不一样。Agent Team 里**每个 teammate 都是独立的、完整的 Claude Code session**——它们有自己的 context window，**互相之间可以直接发消息**，共享一份 task list、自己 claim 任务。Lead 是**协调者**，不是唯一通讯枢纽。

讲义有张对比表，我念一下关键三行：

第一，**Communication**——subagent 只能回报给 main agent；agent team 的 teammates **互相直接发消息**。
第二，**Coordination**——subagent 是 main agent 一手管全部；agent team 是**共享 task list、teammates 自协调**。
第三，**Token cost**——subagent 低，因为结果摘要返回主上下文；agent team 高，**每个 teammate 是一个独立的 Claude 实例**。

记一个口诀：**subagent 是派一个跑腿；agent team 是派一个会议室**。跑腿和会议室是两种不同的工具。

### 怎么开启

非常简单——在你 `~/.claude/settings.json` 里加一段：

```json
{ "env": { "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1" } }
```

或者直接 `export` 一下。开启后 Claude Code 才会响应 "起一个 agent team" 这类指令。

### 怎么起 team

**不需要写任何配置文件**——纯自然语言。

我演示一下，讲义 §2.4 那个例子我念一下：

```
我在设计一个 CLI 工具，追踪代码里的 TODO 注释。
帮我起一个 agent team 从三个角度探索：一个负责 UX、
一个负责技术架构、一个唱反调。
```

就这一句话。Claude 会：
1. 建一个 team，落到 `~/.claude/teams/<某个名字>/config.json`
2. Spawn 3 个独立的 Claude Code 实例——每个自己的 context window
3. 建共享 task list，落到 `~/.claude/tasks/<某个名字>/`
4. 协调它们干完活、汇总结论、最后清理

**官方推荐 3-5 个 teammate**——再多协调开销超过收益。

### 架构四件套

讲义 §2.5 那张表，我口播一下：

**Lead**——起 team 的那个主会话；它负责拆任务、spawn teammates、协调、最后汇总。
**Teammates**——独立的 Claude Code 实例，每个一个 context window。
**Task list**——共享的工作清单，有三个状态：pending / in_progress / completed，还能设依赖。
**Mailbox**——异步消息系统，teammate 之间发的消息会自动送达。

落盘位置：`~/.claude/teams/{name}/config.json` 和 `~/.claude/tasks/{name}/`。

我强调一句——**team config 别手动改**。它存的是 runtime state（session IDs、tmux pane IDs 之类），你改了下次状态更新就被覆盖。

### 两种显示模式

**In-process**（默认）：所有 teammate 都在你主终端里，`Shift+Down` 切换查看。**任何终端都能用**——包括 VS Code 内置、Windows Terminal。

**Split-pane**：每个 teammate 一个独立 pane。要么用 tmux、要么 iTerm2。可以同屏盯全员，但 VS Code / Windows Terminal / Ghostty **不支持**。

我自己实际用下来，**3 个以下 teammate 用 in-process 就够**——切换不烦；4 个以上才上 split-pane。

### Plan approval 流程

对**风险动作**——比如重构 auth 模块、改数据库 schema——可以要求 teammate **先提 plan 给 lead 审批，再实施**。

讲义 §2.7 那个例子：

```
派一个架构师 teammate 重构 auth 模块。
进改动前必须先提 plan 给我审批。
```

Teammate 会在 **read-only plan mode** 工作 → plan 写完发给 lead → lead 自主审批 → 批准后才退出 plan mode 开始改代码。

**关键技巧**：你可以在 prompt 里给 lead 加判断标准，比如"只批通过包含测试的 plan"、"reject 修改数据库 schema 的 plan"——lead 会按这套标准审批。

### 三个 hook 卡质量门

Agent Teams 自带三个新 hook，全是 task / teammate 生命周期相关的：

- `TeammateIdle`——teammate 即将进入 idle 时跑；你可以让它继续干（exit 2 = 反馈给 teammate 让它别停）
- `TaskCreated`——task 被创建时跑；exit 2 拦截创建
- `TaskCompleted`——task 即将标记完成时跑；exit 2 拦截、打回 in_progress

**最实用的应用**——写一个 `TaskCompleted` hook 自动跑 pytest，挂了就 exit 2 把 task 打回。这就把 L6 讲的 "verify before complete" 用 hook **自动绑到了每个 task 上**——不用 teammate 自觉，机器卡死。

### 适合 vs 不适合

适合：parallel code review（3 个 reviewer 分别看 security / performance / test coverage）、debugging with competing hypotheses（5 个 teammate 各自验证一个假说、相互挑战）、cross-layer 重构、新 feature 多模块并行。

不适合：顺序任务、多 teammate 改同一个文件、简单任务。

### 限制（实验性，知道边界）

我快速念一下重要的：**不能嵌套**——teammate 不能起自己的 team。**lead 不能转**——起 team 的 session 终身是 lead。**一次只能一个 team**——要新建必须先 cleanup 旧的。**`/resume` 不恢复 in-process teammates**——session 恢复后 lead 可能找不到原 teammate，要让它重新 spawn。

实验性嘛，这些限制以后可能去掉，但现在用要注意。

## [14:00 — 22:00] §三 Hermes Agent（独立型）

转到第二个主角——**Hermes Agent**。

它和 Agent Teams **截然不同**——**Hermes 是独立平台**。装一次能跑在 $5 VPS 上 7×24 服务你，**通过 8 种入口和你对话**：CLI、Telegram、Discord、Slack、WhatsApp、Signal、Email、Home Assistant。

出品方是 **Nous Research**，**MIT 开源**，GitHub 上 **155k stars**——是 2026 年开源 agent 圈最火的项目。

### 装它（一行）

讲义 §3.2 给了命令：

```bash
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
```

Linux / macOS / WSL2 / Termux 都这一条。Windows PowerShell 也有，但还在 early beta。

装完跑一次 `hermes setup`——它会带你走完整向导：选模型、配 key、开工具。

### 核心命令

我念几个最重要的：

`hermes` 启动 CLI；`hermes setup` 走完整向导；`hermes model` 切模型；`hermes tools` 开关工具；`hermes gateway` 启动消息网关（连 Telegram / Discord 等）；`hermes doctor` 诊断当前安装——这条最实用，装不上时先跑它。

### 会话内 slash 命令

跟 Claude Code 类似，会话里有一套斜杠命令。最常用的几个：

`/new` 或 `/reset` 新建会话；`/model` 切模型；`/personality` 切人格；`/skills` 浏览技能；`/retry` `/undo` 重试撤销；`/compress` 压缩 context；`/usage` 看 token 用量。

### 模型无关——切 Claude ↔ OpenAI

这是 Hermes 一个**杀手锏功能**。它支持 200+ 模型——Nous Portal、OpenRouter、NovitaAI、NVIDIA NIM、OpenAI、Anthropic、Kimi、MiniMax、Hugging Face、自托管 endpoint 等等。

**切换三种方式**：

第一，**`hermes model`**——交互向导，加新 provider 或切已有 provider 都走这个。

第二，**会话内 `/model`**——前提是 provider 已经配过。直接 `/model openai:gpt-4o`、`/model anthropic:claude-opus-4-7`、`/model openrouter:google/gemini-2.0`——一句话切完，**不用改代码、不用改 prompt**。

第三，**改 `~/.hermes/config.yaml`**——直接编辑配置文件。

API key 落 `~/.hermes/.env`，OAuth providers（比如 Anthropic、Google Gemini）token 落 `~/.hermes/auth/` 自动刷新——你不用每次输 key。

**这意味着什么**？意味着你今天用 Claude，明天 Anthropic 涨价了，你 `/model openrouter:某个开源模型` 立刻换——零迁移成本。这是 Hermes 设计哲学：**模型是可替换零件，平台不绑供应商**。

### 持久记忆三件套（这是和 Agent Teams 最大的差异）

Agent Teams 一旦 lead 退出，所有 teammate 的对话**全员消失**——它们是会话内并行，不是持久。

Hermes 完全反着——**自带持久记忆系统**。三件套：

第一，**`MEMORY.md`**——一般知识、事实。Agent 自己往里写。
第二，**`USER.md`**——你的画像。它用一种叫 Honcho 的辩证式建模慢慢了解你。
第三，**FTS5 全文索引 + LLM 摘要**——你三周前聊过的内容它都能搜出来。

**最关键的概念**——**agent-curated memory**。**不是你手写 CLAUDE.md，是 agent 自己 curate**。complex task 跑完它会自动**写一个 skill 存到 `~/.hermes/skills/`**，下次再遇到类似活直接调用——它**真的在自我学习**。

### 多入口 / 多人格

讲义 §3.7 那个 8 个入口表我不一一念。重点说**为什么 8 个入口很重要**——

你早上在地铁上用 Telegram 跟 Hermes 说"今天 review 下昨晚 PR"，到办公室打开 CLI 它已经看完了；中午用 WhatsApp 问个问题，它能 reference 你早上 Telegram 里说过的话——**因为是同一个 agent，记忆是连续的**。

这是 ChatGPT、Claude 桌面这些产品给不了的——它们要么单平台、要么记忆不连续。

### 部署形态

$5 VPS 适合个人长跑；**Daytona、Modal 这种 serverless 形态**——空闲自动休眠、按需唤醒，几乎零成本，比 VPS 还划算；Docker / SSH / GPU 集群 / Vercel Sandbox / Singularity 都行。

**重点提一句 serverless**——这是 2026 的趋势：你的 agent 不用一直 alive，平台帮你管"按需启动"，等于"零成本养一个私人 agent"。

### 适合 vs 不适合

适合：要**跨会话有记忆**的私人 agent；要**多平台触达**；要**自托管开源模型 / 不绑 Anthropic / OpenAI**；长跑任务（日报、周报、夜审）。

不适合：一次性短任务（杀鸡用牛刀）；IDE 级编辑（这是 Claude Code 的强项，但 Hermes 可以通过 MCP 协议**调** Claude Code 来补齐）。

## [22:00 — 24:00] §四 对比 + 选型 + 反模式

### 选型

讲义 §4.1 那张大表我不念了，给你们三句话：

**写代码、要多视角 review / debug** → Agent Teams。
**要长跑、跨周复盘、多平台触达** → Hermes。
**两个都想要** → 一起用。Hermes 通过 MCP 把任务派给 Claude Code，Claude Code 内部又开 Agent Team——**完全可以叠加**。

### 一个核心认知

我特别想强调一句——**agent team 不只是"多个 agent"，是 agent 之间能对话 / 自协调**。这是它和 subagent / 并发脚本最大的区别。

Subagent 是"派跑腿、单线汇报"；并发脚本是"多个进程跑同一份代码"；**agent team 是"派一个会议室，agent 自己开会、互相挑战、得出结论"**。

前一种和后一种**根本不是一个工程问题**——后一种需要 task list 协调、需要 mailbox 通信、需要 plan approval 流程、需要质量门 hook——这些都是 Anthropic 在 Claude Code Agent Teams 这个 feature 里**专门设计的工程基础设施**。

### 反模式三条

**第一**——起 5 个 teammate 干同一件顺序事。**Agent Teams 甜区是并行**，顺序事多人只会互相等。起 team 前问自己"这事能拆成几条互不依赖的线？"——能拆 3+ 条再起。

**第二**——Hermes 装完当云端 ChatGPT 用。Hermes 核心是**持久记忆 + 多入口 + 模型无关**。如果你只 CLI 套壳用，三天后你会觉得不如 ChatGPT。**装完一定要配至少一个消息入口**——让它真的在你生活流里跑一周，你会突然发现它**记得**你两周前讨论过的方案。

**第三**——Agent Team 多个 teammate 改同一个文件。**官方明写：会互相覆盖**。起 team 时 prompt 里就要说清楚谁改哪个目录——把文件所有权显式分到 teammate 上。

## [24:00 — 25:00] §五 作业 + 收束

作业二选一。

**A 方向** —— 跑通 Claude Code Agent Team。开实验 flag → 起一个 3-teammate 的 PR review team（security / performance / test coverage）→ 给一个真实小项目跑一次 review → 提交 lead 的最终 synthesis 输出。

**B 方向** —— 装 Hermes。装完 → 配两个不同 provider（Anthropic + OpenAI）→ 用 `/model` 切换演示 → 接通一个消息入口（Telegram 最快）→ 提交会话截图 + `hermes doctor` 输出。

任一都行——**选你更想真正用上的那个方向**。30 分钟内可完成。讲义 [homework/task1-agent-team/README.md](./homework/task1-agent-team/README.md) 有详细步骤。

最后一句话——**单 agent 时代结束，agent team 时代开始**。前 6 课你都在和**一个 AI** 打交道；从今天起，AI 应该被你理解成**可以被实例化为 N 个、可以互相协作、可以长跑的工人池**。

下节课（Lesson 8）我们进入综合实战——把前 7 课所有工具串起来做一个完整的端到端项目。届时见。
