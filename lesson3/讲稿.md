## [0:00 — 1:30] 开场

好，我们开始。

前两节课，第一课让 AI 从零写 BTC K 线脚本，第二课给 AI 装了 hooks 和 subagent，让它自动检查代码或派独立任务。

## [1:30 — 4:30] §一  MCP 是什么（3 分钟）

好，我们开始第一块。

**MCP 是什么**——我喜欢用一个类比：USB 接口。

电脑本身没有摄像头、U 盘、游戏手柄——但它有 USB 接口。只要符合 USB 标准，任何厂家的外设插上去就能用，电脑不需要知道摄像头里 CMOS 传感器怎么工作，只需要知道"有这么一个外部能力可以调用"。

MCP 给 AI 提供的就是这个：标准接口。你写一个 MCP server，把某项能力——查 SQLite、读 GitHub、调实时 API——暴露给 AI。AI 不需要知道这件事怎么实现，只需要知道"我有 `read_query` 这把手，可以执行 SQL"。

MCP 定义了三类原语。讲义里有一张表，我快速念一下：

第一类叫 **Tools**——AI 可以主动调用的函数。比如 `read_query`，执行一条 SQL；`list_tables`，列出所有表。这是今天我们主要用的那个。

第二类叫 **Resources**——AI 可以读取的数据，更像是静态的，比如一张表的 schema、一份文件的内容。

第三类叫 **Prompts**——server 提供的现成 prompt 模板，人类可以按需调用。

今天我们只碰 Tools，因为查数据库是一个**动作**，不是静态数据，所以用 Tool 最合适。

现在你们手上已经装了 `mcp-server-sqlite`——这是官方的 Python 参考实现，在 PyPI 上，我们用 `uvx` 一行启动，不需要单独 pip install。它一口气暴露了六个工具：`list_tables`、`read_query`、`write_query`、`create_table`、`describe_table`、`append_insight`。Claude 根据你问的问题，自主判断调哪个，你不需要手动选。

最后，和上节课学过的东西对一下：Hook 是**被动触发**的——AI 改文件之后自动跑 lint，AI 没有"要不要触发"的权力；Subagent 是**独立派遣**——你把整件事甩给一个独立上下文去跑；MCP 是**按需调用**——主线 AI 判断"我现在需要查一下数据库"，调用，手缩回来继续说话，上下文连续。三种机制不冲突，可以叠加用。

## [4:30 — 11:00] §二  动手做：装上 sqlite MCP（6.5 分钟）

进入第二块，动手做。

打开终端，我们一步步来。时间够的话你现在跟着跑，时间不够的话先看我演示。

**步骤 1：进 `lesson3/project/` 目录，确认 `uvx` 可用**。

```bash
cd lesson3/project
which uvx || curl -LsSf https://astral.sh/uv/install.sh | sh
```

为什么要 cd 到 `lesson3/project/`——步骤 3 看 `.mcp.json` 的时候你就明白了，先记住这个方向。

`which uvx` 输出路径说明装好了。如果没有，让安装脚本跑完，然后**新开一个终端**让 PATH 生效——这是装完 uv 最常见的坑，不开新终端 uvx 还是 command not found。

**步骤 2：跑 `seed_db.py`，把 30 天 BTC/ETH K 线数据落库**。

```bash
python seed_db.py
```

为什么要这一步？lesson1 的作业存的是点价——某个时刻的快照，没有 OHLC 结构，没法写"过去 30 天最高价"这类聚合 SQL。`seed_db.py` 从 Binance 公共 API 拉 30 天日 K 线，补了一个 `ohlc` 表。这一步只跑一次就够了。

期望看到 stderr 输出：

```
[seed] BTCUSDT: 写入 30 行
[seed] ETHUSDT: 写入 30 行
[seed] 完成，60 行落库到 .../lesson3/project/prices.db
```

如果看到 `requests.HTTPError` 或 connection timeout，说明 `api.binance.com` 被屏蔽。把 `seed_db.py` 里的 URL 改成 `https://data-api.binance.vision/api/v3/klines` 重跑，README 排错表里也有。

**步骤 3：看一眼 `.mcp.json`**——仓库里已经帮你配好了，不需要手写。

```bash
cat .mcp.json
```

你会看到大概这个结构：

```json
{
  "mcpServers": {
    "sqlite": {
      "command": "uvx",
      "args": [
        "mcp-server-sqlite",
        "--db-path",
        "./prices.db"
      ]
    }
  }
}
```

有一个细节要讲清楚，因为这是这节课最常踩的坑：`--db-path ./prices.db` 是**相对路径**，相对的是你**启动 claude 的那个目录**。所以你必须在 `lesson3/project/` 目录下启动 claude，MCP server 才能正确找到 `./prices.db`。如果你在仓库根目录启动，MCP server 会去仓库根找 `./prices.db`，找不到，然后一切静默失败——Claude 可能给你回复，但 SQL 调用会失败，或者提示"表不存在"。

`.mcp.json` 是**项目级**配置，只对 `lesson3/project/` 目录下启动的 Claude 会话生效；全局配置在 `~/.claude/settings.json`，今天不用改它。

**步骤 4：在 `lesson3/project/` 目录启动 Claude，验证 sqlite server 已加载**。

```bash
claude
```

启动之后，在对话框里粘贴：

```
列出当前可用的 MCP server 和 tool 清单。
```

期望看到 Claude 回复里有 `sqlite` server，以及它的工具列表——`list_tables`、`read_query`、`write_query`、`create_table`、`describe_table`、`append_insight`。

讲义有一张排错表，我快速过一下：

- **Claude 说"没有可用 MCP server"**：最大概率是你不在 `lesson3/project/` 目录启动。`Ctrl+D` 退出，`cd lesson3/project`，重启 `claude`。
- **`command not found: uvx`**：装完 uv 之后没刷新 PATH。关掉终端开新的，或者在当前 shell 里 `export PATH="$HOME/.local/bin:$PATH"`。
- **`prices.db` 不存在**：忘跑步骤 2 了。`python seed_db.py` 跑一遍，然后重启 `claude`。
- **拉 K 线失败**：换 `data-api.binance.vision`，如前所说。

大家有跑到这一步的吗？好。

## [11:00 — 16:30] §三  让 AI 自己写 SQL（5.5 分钟）

来到今天的高潮部分。

在刚才那个 claude 会话里，**不要 `/clear`**，继续在同一个会话里粘贴这段 prompt：

```
通过 sqlite MCP 查 ohlc 表中 BTCUSDT 过去 30 天的最高、最低、均价、最近收盘价，
用一段话总结趋势。
```

先停一秒，想一下：如果是你自己来实现这个分析，你会怎么做？大概率是打开 Python，cursor.execute('SELECT MAX(high), MIN(low)...')，把四个数字格式化成一段话回填报告。**你**写 SQL，**你**汇总，**你**生成文字。

现在粘贴 prompt，看 Claude 怎么做。

……

期望看到的对话大概是这样——讲义里有一段示例：

```
⏺ MCP(sqlite/read_query)
  ⎿ [{'max_high': 81323.52, 'min_low': 67732.01, 'avg_close': 75663.88, 'latest': 80933.55}]

⏺ BTC 过去 30 天最高 81,323.52 USDT，最低 67,732.01 USDT，
  均价 75,663.88 USDT；最近收盘 80,933.55 USDT，高于均价约 6.96%...
```

你的数字会和示例不一样，行情每天都在变，正常。

现在我们观察三件事。

**第一个观察**：Claude **自己写了 SQL**——你没给它任何 SQL，你只说了"查最高、最低、均价、最近收盘价"，它就自己出了一条 `SELECT MAX(high), MIN(low), AVG(close), ...` 往 sqlite MCP 扔，拿到结果，再写成一段话。这个能力来自它对 SQL 的理解，MCP 只是给了它"执行 SQL"这个出口。

**第二个观察**：主线对话里你只看到一次 MCP 工具调用 + 一段文字总结，**没有把整张 ohlc 表 dump 出来**。它用了最小的"出口"：只取它需要的聚合值，不多也不少。

**第三个观察是最重要的**，我多说两句。

"给 AI 一个'会写 SQL 的能力接口'，而不是把数据塞进 prompt"——这是 MCP 范式的核心。你可能会想：把 ohlc 表直接 dump 出来，粘进 prompt 不就行了？小数据集没问题，但三年分钟线是几十万行，塞进 prompt 上下文必然爆掉，API 费用也是灾难。更关键的是：AI 根本**不需要看到原始数据**，它只需要"会调用查询的能力"。就像你调用 Python 的 `max()`，你不需要知道排序算法实现，只要知道入参/出参。MCP 给 AI 的是**接口**，不是**实现**，也不是**数据**。

## [16:30 — 19:30] §四  关键认知（3 分钟）

关键认知那一块，讲义写得很清楚，我补充一个往后看的视角。

今天你们是**消费** MCP——装别人做好的 `mcp-server-sqlite`。

Lesson 4 我们反过来：你来**造接口**，把"策略回测"封装成一个 Skill，让 AI 调用你定义的能力。MCP 是"装别人的接口"，Skill 是"你造接口给 AI"，本质都是"让 AI 多一双手"。理解了今天的逻辑，Lesson 4 会非常顺。

还有一点，讲义里有一个口诀，我念一下：

```
Hook  = 有事发生 → 自动做
Subagent = 把整件事交给另一个 AI 去干
MCP   = AI 伸手用一个外部能力，手缩回来继续说话
```

这三个机制互补，不冲突。你完全可以组合：AI 用 MCP 查了数据库，发现阈值触发，hook 自动发通知，subagent 去跑更深分析。这三者组合就是 AI 工作流的基础组件。

## [19:30 — 21:30] §五  权限与安全边界（2 分钟）

权限这块我要认真讲一下，不是废话。

`mcp-server-sqlite` 默认是读写都开的：有 `read_query`，也有 `write_query`、`create_table`。教学场景里我们都开着，方便你看效果。但你回去用到自己的项目时，先想清楚：**AI 真的需要 write 权限吗？**

大多数时候，AI 只需要查数据——只需要 `read_query`，不需要 `write_query`。你可以在 server 包装层只暴露读工具，或者干脆用一个只读用户连数据库。

我去年看过一个团队，让 AI 直接连了他们的生产 PostgreSQL，`write_query` 全开。有一次他们让 AI"修复一些状态不一致的记录"，结果 AI 写了一条 `UPDATE` 把整张表的 `status` 字段都置成 `active` 了——逻辑上说得通，但范围完全错了。如果当时只暴露了 `read_query`，这件事永远不会发生。

记住讲义里的那张表：

- AI 只需要查历史数据：在 server 包装层只暴露 `read_query`，或用只读用户连 DB
- AI 需要写入分析结果：显式给 `append_insight`，不开 `write_query`
- AI 操作生产数据库：**永远不要**——用副本或 read replica，写入走审批流

最小权限原则。接 MCP 之前，先问自己：如果 AI 把这个 server 的所有工具都用一遍，最坏结果是什么？能接受，再接。

## [21:30 — 23:30] §六  反模式（2 分钟）

三个反模式，每个我说一个真实场景。

**第一个：把 MCP 当 prompt 替代品**。

我之前有个学员问我："能不能把项目的 README.md 做成一个 MCP server，让 AI 随时查？"我问他文件多大。200 行。200 行！直接粘进 prompt 完事，做成 MCP 是多一道 IPC 调用开销，收益是零。MCP 的价值在于**按需调用外部动态能力**——执行 SQL、调实时 API、读会变化的数据——不是替代 prompt 喂静态数据。能直接粘的，就直接粘。

**第二个：给一个项目接 20 个 MCP server**。

我自己之前一度装到 12 个 server。每个 server 启动时占一个子进程，所有 server 暴露的 tool 列表合并进 AI 的上下文——tool 数量一旦爆炸，Claude 在选工具时变慢、选不准，有时候它会调错 server。而且每次会话启动都要等所有 server 初始化，我当时每次开 claude 要等将近 8 秒。后来精简到 3 个常用的，瞬间。解决方法很简单：**按需接**，当前任务要用几个就接几个，用完就移，不要把所有可能用到的 server 全挂在一份配置里。

**第三个：让 AI 直连生产数据库或真实交易所写接口**。

这条不用展开太多。`write_query` 开着的时候，一句"帮我清理重复数据"可能变成 `DELETE FROM ohlc WHERE ...`，回滚成本很高。量化策略写接口更是——策略出一次 bug，账户清零。我们今天演示用的是本地 `prices.db` 历史数据，是只读查询，没有任何风险。生产写入，永远走人工审核。

## [23:30 — 25:00] §七  作业 + 收束（1.5 分钟）

作业之前先回答一个你们一定会问的问题：**MCP server 上哪儿找？**

记住几个去处，按"官方度"排：MCP 官网 `modelcontextprotocol.io/examples` 是 Anthropic 背书的参考实现；官方仓库 `github.com/modelcontextprotocol/servers` 收 filesystem、github、git、fetch 这些核心 server；社区聚合最大的是 `awesome-mcp-servers`；想要 web 化注册表看 `mcp.so`、`smithery.ai`、`glama.ai/mcp/servers`，能筛分类、看评分。课件最后一页贴了完整链接，回去对着挑就行。

包本身就两个出处：Node 系发布在 npm（`npx -y @modelcontextprotocol/server-xxx`），Python 系发布在 PyPI（`uvx mcp-server-xxx`）。看 server 文档时，把它给的 `claude mcp add` 命令里的 `command` + `args` 抄到 `.mcp.json` 即可，今天的 sqlite 配置就是这么来的。

好，作业一件事：**再接一个 MCP server**。

任选两个方向：A 方向，接 `@modelcontextprotocol/server-filesystem`，让 Claude 读一份本地文件 + 查 sqlite ohlc 数据，产出一段报告；B 方向，接 `@modelcontextprotocol/server-github`，需要一个 GitHub PAT，让 Claude 拿 repo 的 commit 记录结合行情数据写分析。

主要工作是配置 `.mcp.json` + 设计 prompt，不要求写 Python 代码。30 分钟内可以完成。作业说明在 `lesson3/homework/task1-second-mcp/README.md`，里面有参考的 `.mcp.json.example`。（作业里需要修改 `lesson3/project/.mcp.json`。）

提交三样东西：修改后的 `.mcp.json`（含 token 的脱敏提交）、完整对话片段、三句话感受——两个 MCP 怎么协作的，AI 自动判断还是需要你在 prompt 里提示。

最后说一句：学完这节课，你会接 MCP 了。Lesson 4 我们反过来——你来造接口，把"策略回测"做成一个 Skill。那时候你就是在设计 AI 可以调用的能力，而不是装别人做好的能力。逻辑是对称的，希望今天这节打好基础。
